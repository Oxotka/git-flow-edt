# Синтетическая проверка массовой подготовки файлов — 15 октября 2026

Это исходный замер до перевода автоматической подготовки на всю выборку.
Результаты новой реализации — в [отдельном отчете](2026-10-15-staging-whole-selection.md).

Проверена текущая реализация `WorkingChanges.stage(..., monitor)` с пачками по 32 файла.
Для сравнения в тестовом модуле повторены вызовы того же `stage(..., files)` пачками по 128, 512 и всей выборкой.
Рабочий алгоритм плагина и размер пачки не изменялись.

## Среда и методика

- macOS 27.0.1, ARM64, Java 21.0.11; JGit 6.8.12 из target EDT 2026.1.3.
- 1000 и 5000 выбранных файлов; примерно поровну измененных, удаленных и новых.
- Пути вида `src/CommonModules/Module00001/Ext/Module.bsl`, содержимое около 2 КБ.
- Отдельно присутствуют частично подготовленный файл и новый файл вне выборки.
- Перед каждым замером восстанавливаются одинаковые байты индекса; рабочие файлы остаются теми же.
- Четыре круга с ротацией порядка стратегий, предварительный прогрев на 120 файлах.
- Время включает только подготовку; создание файлов, восстановление индекса, проверки и удаление временного репозитория исключены.
- Файловый кеш и база объектов прогреты. Это не замер холодного диска и не тест UI EDT.

## Результаты

Медиана четырех замеров, секунды.

| Выбрано файлов | Пачка 32 (текущий код) | Пачка 128 | Пачка 512 | Вся выборка |
|---:|---:|---:|---:|---:|
| 1000 | 0.632 | 0.216 | 0.106 | 0.088 |
| 5000 | 13.631 | 3.826 | 1.371 | 0.466 |

Все варианты дали ожидаемые наборы добавленных, измененных и удаленных файлов в индексе. Частично подготовленный файл сохранил разные версии в индексе и рабочем дереве; файл вне выборки остался untracked; HEAD не изменился.

В проверке отмены сигнал устанавливается при сообщении о первой пачке. Текущий код завершает эти 32 файла и возвращает CANCELLED перед следующей пачкой. Проверен точный список оставшихся новых файлов и сохранение частично подготовленных изменений.

На этой выборке повторные небольшие пачки дают заметные накладные расходы. Варианты 128/512 заслуживают отдельной проверки отклика отмены перед изменением плагина. Вариант всей выборкой не имеет промежуточных проверок отмены. Результаты нельзя переносить без проверки на Windows, другие диски, крупные/двоичные файлы и работу одновременно с EDT.

## Повторный запуск

```bash
./.tools/bin/mvn verify -Dtest=WorkingChangesBenchmark
```

Бенчмарк запускается явно по имени класса и не входит в обычный `verify`. В нем нет порогов времени: он проверяет корректность и печатает результаты. Временные репозитории удаляются после каждого сценария.
