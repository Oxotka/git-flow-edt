# Согласование переключения веток с EDT

## Подтвержденные факты

Git Flow переключал файлы через JGit, а обновление проектов планировал после
операции. Штатный checkout EDT вызывает до и после смены ветки
`IGitIntegrationManager.beginManagedCheckout(Repository, Ref, IProgressMonitor)`
и `endManagedCheckout(Object)` из `com.e1c.g5.v8.dt.snapshot.integration.git`.
Сигнатуры и порядок вызовов проверены по установленной EDT 2026.1.3+25.

В предоставленном снимке рабочей области при активном master карта ресурсов
проекта совпадала с индексом базы другой ветки: 72 747 записей, включая
подписи и идентификаторы ресурсов. У баз отдельные индексы; общий ConfigDumpInfo
этими данными не подтверждается. После переключения обновление запрашивал
также штатный запуск из панели приложений.

## Изменение 0.17.1

UI передает core исполнитель checkout. Он получает штатный OSGi-сервис EDT,
начинает согласование, переключает ветку и завершает согласование в finally.
Завершение вызывается только для ненулевого handle. Создаваемая ветка получает
реальный Ref до подготовки EDT; при ошибке он удаляется, только если не стал
текущим и не изменился. Tracking-настройки сохраняются.

Согласование охватывает именно checkout, между сохранением и восстановлением
локальных изменений. Возврат в исходную ветку при конфликте также согласуется
с EDT. При ошибке после переключения оставленный stash явно указывается
в результате вместе с признаком изменения рабочей области.

Сервис обнаруживается во время выполнения, чтобы не делать snapshot bundle
обязательной зависимостью. При отсутствии bundle остается прежний путь JGit
и refresh. Если bundle есть, но сервис недоступен или подготовка завершилась
ошибкой, операция возвращает ошибку с сохранением локальных изменений.
Ожидание регистрации сервиса ограничено 10 секундами, поддерживает отмену
и выполняется в Job. Штатные настройки синхронизации баз не меняются.

## Проверки и ограничения

Тесты используют временные Git-репозитории и подмену менеджера EDT: порядок
begin/checkout/end, отмена, ошибки каждого этапа, сохранение первичной ошибки,
создание и очистка ветки, upstream, сохранение staged/unstaged/untracked,
откат при конфликте и сообщение об оставленном stash.

Полный `mvn -o verify`: 128 тестов, 0 ошибок и пропусков.

Эти тесты не подтверждают восстановление реальных снимков автономных баз.
Поддержка API проверена по EDT 2026.1.3+25; другие версии требуют проверки.
Пользовательские базы и ветки при разработке не переключались и не обновлялись.
Для проверки результата нужны два заранее обновленных автономных приложения:
ветка A → master → A → master, запуск после каждого переключения, без правок.
Повторного предложения загрузить различия между ветками быть не должно.

При ревью выявлены ограничения, не входящие в этот выпуск: возврат после
конфликта из detached HEAD может оставить локальные изменения в stash вместо
автоматического восстановления, а отмена подготовки отображается как ошибка
операции. Обычное переключение именованных веток проверяется отдельно от этих
сценариев. Исходные изменения при неудачном возврате остаются в stash.
